# Why a small development record is retained

We present clean final outcomes in the main reader route and preserve development history separately. `packet_development_context.zip` records earlier transport and qualification attempts so that readers can inspect the failure-and-repair evidence without confusing partial attempts with completed comparative episodes.

This is an optional companion release asset, not an original dataset or a prerequisite for a new final-v7 experiment. It is included locally but excluded from Git history. See [the asset guide](../ASSET_GUIDE.md#development-history) for access, exact placement and interpretation; [the catalogue](../RELEASE_ASSETS.json) records its size and SHA-256. Its public download URL remains unset until publication is approved.

Past operator actions and failed attempts cannot be regenerated as historical evidence. We therefore retain the originals and recommend the final v7 protocol for new work. Do not execute old machine-specific launchers or rerun failures to imitate this history. Keep any failures encountered in a new experiment as new evidence.

We completed the bounded initial PoC. The larger confirmatory study remains future work. Ineffective actions, measured overload and benign-traffic collateral effects remain visible in the final outcomes. Separating this historical archive does not remove or reclassify those measured findings.
