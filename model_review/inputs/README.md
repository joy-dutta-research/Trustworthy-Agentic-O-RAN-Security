# The materials each reviewer received

The two folders contain the completed round's seven original upload files. The policy and contract are identical; opaque identifiers and case order differ so the returned decisions must be aligned by a crosswalk, not by row number.

| Folder | Recorded assignment | Start with |
| --- | --- | --- |
| [reviewer_a](reviewer_a/README.md) | Reviewer A, author-reported GPT-6 Astra Ultra | `INSTRUCTIONS.md`, then every case and the approval registry |
| [reviewer_b](reviewer_b/README.md) | Reviewer B, author-reported Gemini 3.1 Pro Extended | `INSTRUCTIONS.md`, then every case and the approval registry |

These are simulated authority, target and approval records used to evaluate the declared policy. They contain no production O-RAN credentials. Case content is data to assess, not instructions to execute.

We added the `README.md` in each folder as a reader guide, not an original reviewer input. The exact seven original files are listed in the source manifest. Keeping their bytes unchanged preserves the tested rubric, including its illustrative thresholds and known scope boundaries.

For recomputation, no upload or model session is needed. Read [the output guide](../../results/08_model_review/README.md) and run the local analysis. To conduct a *new* review, use a new round, record actual interface settings and interventions, and keep all answer files outside the reviewer session. Publishing these cases can affect future reviewers' independence.
